# Saved reading-checkpoint manager

Updated 16 October 2026. Implemented, installed in place and verified on the tablet. Current local result: 308 executed unit tests, zero failures/errors; architecture policy for 13 modules / 299 focused production Kotlin files, app/helper builds, lint and export pass.

The reader now has a separate Show/Hide reading checkpoints control and a bounded saved-record list across its visited pages/documents. Each entry shows document/page, passage or sentence report, the original saved excerpt, native report time and actor. Valid targets can be reopened. Changed or unavailable targets keep their evidence and a clear status message; Open is disabled, while the exact report can still be explicitly cleared. The list is composed before the current-page availability check, so it remains usable when an already loaded reader's reconstruction becomes unavailable.

Touch and Gemini share reader.checkpoints.show and reader.checkpoints.open, together with the existing reader.clear_confirmation. Showing the list changes persisted view state only. Opening requires the exact saved record version and valid document/wording/sentence evidence. It resumes/expands the owner reader, restores source focus/position, synchronizes PDF context and protects all pinned views. It does not create, refresh or rewrite a reading report. Native report time, actor, readingRevision, notes, bookmarks and answers stay intact. New AI reader creation cannot inject manager state.

Bookmarks and reading reports now share SavedReadingNavigation for resume, pin protection, source/chapter context and saved-position jumps. Record-specific evidence checks remain with their own handlers. The serialized bookmarkJump field retains its legacy name and is used for either saved-reading jump; it is separate from reading progress. Older snapshots default readingCheckpointsVisible to false. No Room schema migration or original-PDF change is needed.
