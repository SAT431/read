# Native practice timer

Status, 16 October 2026: implemented, installed in place and verified on the connected Android tablet, including live Gemini controls. This is an advisory timer within the quiz renderer. It is not an alarm, notification or automatic exam-grading feature.

The compact presentation shows stopwatch/countdown mode, elapsed time, optional remaining time, status and Start/Resume/Pause. Timer options expands duration/reset controls. The duration editor accepts a total of 1–86400 seconds or an unlimited stopwatch. Setting duration preserves counted time; reset preserves the duration, answers, confidence and prior attempts. Timeout explicitly shows that answers remain available and does not submit or check them. Timer data belongs to the quiz attempt, independently of its visual component.

Touch and Gemini use the shared native actions quiz.timer.start/pause/reset/limit/expand. Exact attempt/version guards reject stale changes, hidden/suspended quizzes and historical review. The model cannot supply elapsed time, status or timestamps, nor inject a timer into a newly created quiz. Expanding controls changes presentation without restarting the monotonic anchor or rewriting the last time-control actor. Its app revision changes, while timer.version stays unchanged.

WorkspaceSession owns runtime checkpoints using a process-local monotonic clock. Android supplies SystemClock.elapsedRealtime. A one-second UI loop updates elapsed state without changing semantic app revision or timer.version, allowing an already captured Gemini pause request to commit. Expiry, automatic pause and time controls change semantic state; stale responses then reject normally. SnapshotWriter orders both semantic revisions and same-revision checkpoints, so older queued writes cannot overwrite a newer awaited save. Room encoding/writes run on the IO dispatcher.

Suspension, hidden/capsule presentation, historical review, leaving practice and backgrounding pause the timer automatically. Assistant opened from Workspace remains eligible so talking to it does not stop counted practice. Returning requires explicit resume. The lifecycle observer skips configuration-change stops to retain timing during rotation; a focused actual-orientation test passed with the same native observer, and actual MainActivity separately retained its graph/state through recreation. See RECOVERY_ACCEPTANCE.md. Backward monotonic time pauses with a clock-interruption reason. Bounds prevent unbounded elapsed time and timer-control versions.

Starting another quiz attempt freezes the old timer with its saved answer/key/source record and creates a fresh timer. Older snapshots without recorded historical time retain null, displayed as unknown. Process recovery pauses a previously running timer at its last durable checkpoint; it does not estimate time while the process was absent. An abrupt kill can lose the most recent unflushed interval. There is no background service or guaranteed exact-time alert.
