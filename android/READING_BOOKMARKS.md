# Native reading bookmarks

Status, 16 October 2026: implementation, unit tests, app/helper builds, lint and export pass. The build is installed in place; native UI/storage, live Gemini and enlarged-text tablet checks passed.

The reader provides a separate bookmark glyph and passage/selected-sentence action, a current-reading-position control, and a saved list with Open/Remove. The list can be shown or hidden through touch or AI. It stays available when the current page cannot be reconstructed. Bookmarks belong to the reader activity, survive hidden/suspended components, and remain independent of annotations, private drafts, quiz answers and layout undo. The list spans the pages/documents visited by that reader; this is not a global bookmark-search feature.

An explicit sentence bookmark stores its deterministic source sentence ID. Passage bookmarks store the exact source element. Saving the current reading position resolves the native top visible source element and pixel offset rather than accepting model coordinates. Opening uses current source order to find the element and a persisted jump sequence to restore its position even if it is already visible. Reader scroll observation is keyed by document and page, preventing a same-page-number document switch from retaining the previous list observer.

Native records include immutable document checksum, source anchor, optional sentence ID, wording fingerprint, source excerpt, save time, actor and a creation sequence. No model-supplied wording or timestamps become bookmark evidence. Opening requires the same document identity, saved wording and sentence target. Changed or unavailable targets remain listed with their original excerpt and a clear message; they are not silently retargeted or deleted. Explicit removal remains available. A corrected passage therefore requires a new bookmark if its saved wording no longer matches.

Shared actions are reader.bookmark.add, reader.bookmark.open, reader.bookmark.remove and reader.bookmarks.show. Open/remove require expectedCreatedRevision from the saved record. This is the owner's monotonic bookmark edit sequence, distinct from app revision; it advances through removals and ID reuse, including inside atomic batches. The snapshot persists the sequence. Batches fail atomically; stale IDs/creation sequences, wrong pages/sentences, duplicates and limits reject. AI cannot inject saved records into new-reader creation. Opening protects every pinned visual instance of the shared reader and the normal assistant interaction guard. Native UI and Gemini execute the same handlers.

Bounds are 200 bookmarks per reader, 160 excerpt characters, a 1,000,000 bookmark-edit sequence and a separate 1,000,000 jump sequence. These are implementation bounds, not learning-progress measures. Snapshot additions are backward compatible: older readers default to an empty list and zero sequences. No Room schema migration or source-PDF mutation is needed.
