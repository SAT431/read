Delivered and verified 16 October 2026. This supersedes the single-PDF-only parts of DOCUMENT_STUDY.md. Native source-reference composition preserves original PDFs; arbitrary source-file editing and model-generated code execution are outside this implementation.

## Native tools and source ownership

| Tool | Actual native behavior |
|---|---|
| harness.analyze_pdf | Load/resume validated original-PDF batch mapping for any imported PDF without leaving the active study. |
| harness.browse_topics | Discover/filter/page exact native topic links in any PDF; request missing mapping first. Forty results per page. |
| harness.open_topic | Open that PDF's study, select one linked topic, focus its original page range and prepare source text/original image pixels. |
| harness.inspect_topic / harness.inspect_page | Open an exact original topic/page; Back restores the destination study, including cross-PDF inspection and diagram enlargement. |
| harness.include_topics | Insert selected topics from another PDF into the current reading page, preserving its cursor, native source links and learner records. |
| harness.remove_source | Remove a reference only; retain original/cache/notes/reports and invalidate scheduling for the removed selection. |
| study.select_topics / begin / page / sentence / guide / finished_line | Shared exact selection, native extraction, cross-source navigation, guided focus and explicit reading confirmation. |
| source.engineer_page | Existing bounded original-page extraction, Gemini reconstruction, native crop generation and local cache. |

Gemini selects tools/semantic targets; Android validates and executes prebuilt functions. Original PDFs are immutable evidence. Adding material means a source-linked reading composition, not silently rewriting PDF bytes. SourceDocument checksums, complete map fingerprints, topic/page ownership, plan versions, pins/writing guards and explicit confirmation remain enforced.

StudySourceSelection is additive durable state inside DocumentStudyPlan. It retains PDF ID/checksum, full map fingerprint, topic IDs and derived pages. Its optional StudyPlacement captures the native source/page focused when material is added. StudyComposition inserts original-linked sections after that page; adding content no longer requires a separate collection page. Legacy unplaced selections remain readable. Nested insertions are ordered without duplicate pages or cycles. Removing a parent reference reanchors retained children; changing primary topics reanchors removed insertion points without erasing source selections.

StudySources projects ordered original pages and sentences. activeSourcePdfId and pageIndex identify the focused source while navigation.pdfId remains the destination study. Each inline section has a source/page label and Original link. Sentence/source focus and guidance retain original ownership. Starting guidance prioritizes the focused source page; only explicit confirmation records reading, then the guide follows insertion order. Removing references cannot delete saved source activity or reports. Explicit resume restores attached-source focus; ordinary Study with AI opens topics first. The bounded assistant compositionSurface describes planned source references, not proof that every section is loaded, visible, correct or read.

## Jobs, tool discovery and captured evidence

PdfHarnessAwaiter joins app-owned topic mapping and selected-source preparation under the existing bounded three-round/90-second assistant turn. Mapping completion is explicitly different from readable source completion. Cancellation or target changes stop follow-ups, while an already-started native job may finish caching without navigating. Analysis effects carry native request IDs so dispatcher/awaiter delivery cannot retry the same failed attempt twice. Completed map batches persist; explicit new attempts can resume. Preparation versions invalidate old scheduling/progress after selection/removal changes.

MentorToolDirectory lets Gemini choose up to two relevant tool families from the complete native directory when the available set is large. Execution uses serializer-derived typed schemas for those families, followed by all existing native execution checks. It does not execute code, permanently hide capabilities, or use keyword-only routing. Flat nullable JSON-schema types reduce redundant unions. Google documents nullable type arrays and warns that large/deep schemas may be rejected in its [structured-output reference](https://ai.google.dev/gemini-api/docs/structured-output). No-tool answers use a null batch schema instead of an empty command union.

MentorRequestScope keeps core rules and source evidence, sends selected contracts and omits unrelated component metadata. Harness/navigation-only calls omit the large detailed quiz/notes/layout reference; full reference remains for the appropriate families. The source-linked harness instructions remain in the core orchestrator prompt. This reduces request bloat rather than extending deadlines or weakening source checks.

MentorHarnessBinding supplies map freshness proofs from the exact captured native source snapshot after verifying the chosen PDF/topic IDs. The model cannot substitute the current PDF's fingerprint for a second PDF. It never looks up newer evidence after the response: runtime still rejects a captured map if it changed while the request was in flight.

## Figure extraction and compatibility

LocalPageEngineer retains the model's source bounds and separately records mediaBounds for a conservative original-page-width crop with bounded vertical context. This addresses cropped side labels seen in the Cell screenshot. FigureAssetUpgrade can backfill older cached figure assets locally, preserving source IDs/wording and learner references without another Gemini call. Actual native crop bytes remain private cached PNGs. PageModelValidator checks crop containment and page bounds. Local selected-page copies preserve inherited rotation, media/crop boxes and resources.

A conservative strip may include surrounding content. It is not proof that model topic boundaries, transcription, or every figure label are correct. Full source inspection stays available; reconstructed pages remain UNCHECKED.

## Compact interface

Topics use short selectable rows and direct original-page links. Overviews/subtopics and one-topic reading are in each row's secondary menu. The toolbar holds the title and reading/topic toggle, with original/source tools behind a menu. The original viewer also has a single compact navigation row, processing/comparison/zoom tools in its menu, a full-height viewport and the same compact companion. Fit page reverses Fit width. Duplicate large titles, idle processing panels and global voice bars no longer occupy the original view. PDF sources appear in a sheet (this chapter by default, all PDFs available), with multi-topic addition and reference removal. The companion starts as a compact strip; history/composer open in a modal sheet and keep drafts on closing. Guided controls and reply/error notices remain visible without a permanently expanded pane. Reader pages show source PDF/page provenance when combined. The source sheet wraps short content and caps/scrolls longer lists instead of reserving most of the screen for one topic. Enlarge original beside a diagram opens the full-screen source viewer. Stable list keys/cursor targets and retained immutable decoded images prevent source-cache updates from resetting the visible reading position. A minimum navigation-row height prevents a newly available Next button from shifting the document.
