# Explicit reading checkpoints

Status, 16 October 2026: native implementation, 294 unit tests, architecture policy (13 modules / 296 production Kotlin files), app/helper builds, lint and export pass. The build is installed in place and focused native UI/storage, live Gemini and enlarged-text tablet checks pass. This work does not establish production readiness.

The reader now offers separate guided-position and page-progress components. Confirm passage read records an explicit whole-passage report. Selecting a sentence changes the control to Confirm selected sentence read. A margin marker shows the latest still-valid report on the current page, with its source excerpt and assistant attribution when applicable. Clear reading confirmation removes the exact selected report. The controls use the shared reader.confirm_read and reader.clear_confirmation native actions.

The page bar counts nonblank paragraphs, captions and lists. A passage counts as confirmed after its explicit whole-passage report or explicit reports for all its current sentences. Sentence checkpoints have a separate count. Whole-passage reports do not invent individual sentence reports, and overlapping passage/sentence records do not count a passage twice. An empty page has no progress denominator. Scrolling, selecting text, focusing a sentence, bookmarking, elapsed time and quiz results never create reading reports.

Records retain immutable document identity, exact source/sentence, wording fingerprint, original source excerpt, native report time, actor and a per-reader edit version. Source wording changes leave the old record saved but exclude it from current progress and the marker. The page header reports outdated checkpoints. Reconfirming the same target replaces its latest report with current source evidence; this is a latest-checkpoint map, not an exhaustive chronological reading history. Paragraph-level controls can clear an older whole-passage confirmation. The saved-checkpoint manager now exposes retained sentence/document reports across this reader, including changed or unavailable targets; they can be explicitly cleared. See READING_CHECKPOINT_MANAGER.md. Cold workspace/source-cache repair and other record families remain separate acceptance work.

Confirmed reports live in reader activity data independently of visible components, annotations, bookmarks, answers and layout undo. Native readingRevision persists across confirmations and removals; stale clear/reconfirm commands reject. Creation cannot inject reports through a new AI reader. Only the current active visible reader page can receive reports, and normal assistant interaction protection applies. There are at most 1000 saved reports per reader and a 1,000,000 edit-sequence bound. Existing snapshots default to no reading reports; an older saved scroll position is not migrated into confirmed progress.

Gemini receives actual native records and a readingProgress projection for each reader's current available page. Missing source pages do not receive a fabricated progress summary. The projection is based on the currently available reconstructed/approved wording; it is not a claim that every original PDF page has been processed, that a chapter is complete or that its content is understood. Repeated report saves retain the latest report for that exact target. Original PDF bytes, machine wording, corrections and learning reports stay separate.

Shared source identity/wording checks now serve bookmarks and confirmations through ReadingTargetResolver. Page progress indexes sentences and paragraph fingerprints once per projection, rather than recompiling the whole source for every saved record. Bookmark sentence checks resolve only the relevant element. This is an implementation improvement; sustained device performance remains unmeasured.

Twelve new unit cases cover non-inference from scroll/focus/bookmarks, complete sentence coverage, native time/actor, stale reports and replacement IDs, wrong/hidden targets, changed-wording retention, answer/bookmark/undo preservation, malformed/injected reports, empty denominators, atomic batches/wire actions, provider projection and additive snapshot recovery. Existing bookmark and timer tests are rerun with the shared resolver. ReadingConfirmationUiTest, ReadingConfirmationStorageTest and LiveReadingConfirmationTest executed and passed for sentence/passage controls, isolated Room reopen and real Gemini explicit report/clear. The shared ReadingStateLargeTextUiTest passed at 1.8 font scale, including clearing a whole-passage report while a sentence is selected; artifacts/qa/reader-state-large-text.png was inspected. Quiz/memory/revision regressions and the actual installed Learning route passed. App/helper updates preserved keys/PDFs and normal Folio was cold-launched afterward. These checks are part of 16 distinct tablet tests in this run. Additional focused orientation and fresh-process checks retained native reports and other learning state; see RECOVERY_ACCEPTANCE.md. Broader TalkBack/accessibility, complete UI/editor restoration and unfinished-write interruption, real-source fidelity, stale-source cleanup and full tutor/provider acceptance remain open, alongside the complete catalogue and release gates.
